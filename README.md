## 页面结构

页面采用“技术案例索引”方向：同一白底蓝色品牌下，以目录浏览三个案例。手机首先呈现目录、智慧水产 AI 助手、本人职责和实际运行截图。

- **智慧水产 AI 助手**：业务问题、本人工作、项目价值，以及独立的 RAG 知识检索路径和设备工具调用路径。六项工程证据按工作流、知识检索、业务 API 筛选展示。
- **移动端业务入口**：作为 AI 助手主项目的一部分，展示移动端原型、消息交互和现有 Vue2 页面迁移适配职责。
- **智慧增殖放流站 Web 原型**：已有业务流程、页面迁移与迭代、状态操作和跨模块异常工单衔接。
- **数字孪生养殖监控**：数据驾驶舱布局、图表展示、视频墙与页面切换等交互原型。
- **能力与联系**：按已实践、基础、学习中/了解呈现能力，提供邮箱、GitHub 源码和 AI 项目经理作品集入口。

所有关键图片使用统一的模态查看器，支持上一张/下一张、左右方向键、Escape、焦点循环和关闭后归还焦点，并提供原图链接。页面包含证据筛选状态动画、操作按下反馈和首屏图一次入场；尊重系统“减少动态效果”设置。

## 真实内容范围

AI 助手案例展示通过 Dify 可视化流程参与的资料整理与 RAG 配置、意图分类、参数提取、设备 ID 映射、已有业务接口调用、JSON 返回处理及异常分支。

知识问答通过检索片段生成带来源的回答；设备状态和水质数据来自已有业务 API。截图用于说明配置与运行过程，不表示性能指标、用户规模或商业成果。

移动端目前是交互原型。线上版本在服务不可用时显示网络异常，该画面不作为成功调用真实服务的证据。Dify 和原业务接口属于独立服务；本静态作品集不会运行这些服务，不包含 API Key，也不发起实时业务接口调用。

Web 和数字孪生案例的个人角色限于页面、交互原型、迁移适配与持续迭代，不表示本人负责完整生产后端、数据库、数字孪生引擎或识别模型训练。Python 和相关基础知识保持基础级别；FastAPI/vLLM 保持学习中，LoRA/Serving/量化等保持了解。

## 本地运行

从两个网站共同所在的根目录 D:\ai学习\个人网站 启动静态服务：

```powershell
python -m http.server 8877 --bind 127.0.0.1
```

打开 <http://127.0.0.1:8877/ai-application-engineer-portfolio/>。

页面保留 React 18.3.1 UMD、ReactDOM 18.3.1 与 Babel Standalone 7.26.10 的现有 CDN 加载方式；CSS 在 index.html 内联，不需要安装 npm 依赖或构建。首次打开需要网络加载上述依赖。

与经理站及原型的链接使用相邻仓库的相对路径。在共同根目录本地预览和同域 GitHub Pages 部署下均可访问；单独将本仓库作为服务根时，需要另行提供相邻原型仓库。
